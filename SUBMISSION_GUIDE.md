# SIH Submission Guide

## 1. Repository readiness

- Keep the repository public and accessible.
- Ensure the README reflects the final project and problem statement.
- Remove or avoid secrets, API keys, tokens, or local environment files.
- Verify that all required project folders are present and correctly named.

## 2. Submission checklist

- [ ] README completed with project information, problem statement, solution, and setup steps
- [ ] Architecture documentation added under `docs/architecture.md`
- [ ] Demo video link added in `submission/DEMO.md`
- [ ] Presentation or PPT link added in `submission/PRESENTATION.md`
- [ ] Screenshots stored in `assets/screenshots/`
- [ ] App runs using the documented commands
- [ ] Deployment instructions are included if applicable

## 3. Demo submission

- Add a concise project overview and explain the model workflow.
- Highlight the use case, stakeholder impact, and deployment readiness.
- Demo the upload-to-prediction flow and major dashboard features.

## 4. Review notes

- Keep labels, names, and file references consistent.
- Provide enough context for evaluators to understand the solution without external explanation.
- Prefer a clean and polished repository structure over cluttered or incomplete content.
